# Remember Me 第一幕新增素材与修改教程

本包基于你本次提供的 `RememberMeAct1` 和 `RememberMeScript.docx` 整理。所有新增文件、修改后的数据副本都在本文件夹内，原工程没有被改写。

**推荐按下面的教程，在另一台电脑的工程副本中逐项修改。不需要运行本包的任何 Python 或 JavaScript 工具脚本。**

## 按这个顺序做

1. 在另一台电脑关闭 RPG Maker MV，把完整工程文件夹复制一份，命名为 `RememberMeAct1_Enhanced`。后面只打开这一份里面的 `Game.rpgproject`。
2. 阅读 [01_人物素材导入.md](01_人物素材导入.md)：新增叔叔、阿姨、爷爷的脸图和行走图，指定事件图像。
3. 阅读 [02_闪回与结尾逐步修改.md](02_闪回与结尾逐步修改.md)：修正站位、后退动作、声音与妈妈走近的衔接。
4. 阅读 [03_游玩体验逐项设置.md](03_游玩体验逐项设置.md)：处理重复调查、妈妈提示、互动提示、菜单和音量。
5. 阅读 [04_更换英文字体.md](04_更换英文字体.md)：更换窗口字体、字号及描边。
6. 按 [05_另一台电脑验收与排错.md](05_另一台电脑验收与排错.md) 在安装 MV 的电脑上自行检查。

需要逐条对照事件指令时，打开 [06_事件指令对照.md](06_事件指令对照.md)。这是修改后数据的可读清单，不是可以直接粘贴进 MV 的事件代码。

不方便阅读 Markdown 时，用记事本打开 `教程_纯文本.txt`。

## 文件用途

| 文件夹 | 用途 | 要不要复制进工程 |
|---|---|---|
| `assets/img/faces` | 三张新脸图表，每张含八个表情 | 要，复制到工程同名目录 |
| `assets/img/characters` | 三张单人行走图表 | 要，复制到工程同名目录 |
| `assets/js/plugins` | 互动体验插件、字体插件 | 按教程选择安装 |
| `assets/fonts/gamefont.css` | 修正字体来源与实际文件扩展名 | 按字体教程安装 |
| `patch_data` | 本轮工程版本对应的四份修改后数据库文件 | 手动点击修改时**不要复制** |
| `generation` | 生成原图、英文提示词、自定义字体 CSS 示例 | 不复制进游戏 |
| `review` | 检查记录、源文件指纹和中途预览截图 | 不复制进游戏 |
| `tools` | 生成和检查过程的辅助脚本 | 不需要运行 |

## 如果希望直接导入数据副本

只有另一台电脑的工程仍与本次提供的版本一致时，才适合整文件导入。若你已在那里继续改过地图或事件，使用手动教程。

1. 关闭 MV，先备份完整工程。
2. 将 `assets` **里面**的 `img`、`js`、`fonts` 按同名目录合并进新工程。不要把整个 `assets` 当作游戏目录；不要删除或替换整个 `img`、`js` 文件夹。
3. 将 `patch_data` 内的 `Map001.json`、`Map002.json`、`System.json`、`Actors.json` 复制到新工程的 `data`，替换这四个文件。此操作会整体替换这两张地图的事件及系统设置，只在备份后的新副本中做。
4. 打开新工程。按 03、04 教程启用两个新插件；停用旧的 `RM_Act1_Polish`（如果启用过）。可停用 `MadeWithMv` 跳过启动展示页。
5. 选择 **New Game**。不要用原版本中途存档判断事件修改是否生效。

采用这条路线后，无需再手工修改 01—03 中已经写入数据的内容。字体插件和体验插件的启用仍需手动完成。

## 剧本边界

保留墓园探索、看墓碑、爸爸流泪、家中闪回、回到墓园、遗物箱与第一幕结束的顺序。闪回英文对白逐句保留。新增爷爷只增加现场存在感和一句观察，不增加往事、解释或任务。阿姨保留原工程“手里攥着纸巾”的观察，不新增姓名。

原剧本没有指定叔叔、阿姨的精确年龄。新素材按中年亲属处理，这是美术选择，不是新增剧情事实。爷爷沿用原图表右上角年长男性的形象，另配新脸图。

## 当前交付状态

在你要求停止本机运行之前，做过一次浏览器中的事件流程检查；那不等于 MV 编辑器或另一台电脑的验收。按你的新要求，现已停止本机预览，后续只修改交付文件与教程。

最后补充的字体插件、CSS，以及闪回中爸爸朝向的微调**未运行验证**。`review` 的截图与运行记录来自此前版本，不能当成最终版本的运行证明。最终验收请按 05 在另一台电脑完成。


# 人物素材导入与事件设置

## 一 复制图片

关闭 MV，将本包中的以下文件复制到工程副本的对应目录。不要改文件名，尤其不要删除行走图前面的 `$`。

| 文件 | 放入工程 | 格式 |
|---|---|---|
| `RM_Face_UncleJames.png` | `img/faces` | 576×288，八个 144×144 脸图格 |
| `RM_Face_Aunt.png` | `img/faces` | 同上 |
| `RM_Face_Grandpa.png` | `img/faces` | 同上 |
| `$RM_UncleJames.png` | `img/characters` | 144×192，单人 3列×4行 |
| `$RM_Aunt.png` | `img/characters` | 同上 |
| `$RM_Grandpa.png` | `img/characters` | 同上 |

行走图四行依次为下、左、右、上；每行中间是站立帧。它们是已经排好格的透明 PNG，不需要你裁图。爷爷行走图提取自原 `RM_Family` 的年长男性，不会改动原图表。

脸图索引从 0 开始：上排从左到右 0、1、2、3；下排从左到右 4、5、6、7。大致表情依次为平静、关切、垂眼、倾听、说话、闭眼、悲伤、安慰；实际以图像为准。

## 二 替换叔叔的事件图像

1. 打开 `Act1_Cemetery`，切换事件编辑模式。
2. 双击坐标 **(8,9)** 的事件 **007 UncleJames**。坐标以地图左上角 (0,0) 为起点，可看编辑器状态栏。
3. 在第 1 页左下角双击“图像 / Image”，选择 `$RM_UncleJames`，选择**第一行中间帧**，确定。
4. 双击已有“显示文字 / Show Text”，脸图改为 `RM_Face_UncleJames`，选**下排最右格，索引 7**。
5. 保留下面的英文，不改主线开关：

```text
\C[3]UNCLE JAMES\C[0]
Take your time, Grace.
```

6. 优先级保留“与人物相同 / Same as Characters”，触发保留“确定键 / Action Button”。保存。

## 三 替换阿姨的事件图像

1. 打开墓园 **008 Relative**，坐标 **(17,10)**。事件名称可改为 `Aunt`。
2. 图像改为 `$RM_Aunt`，第一行中间帧。
3. 原来的“显示文字”脸图改为 `RM_Face_Aunt`，选**上排第三格，索引 2**。
4. 保留观察式文字，不把这句话改成阿姨自己说的话：

```text
\C[7]
She holds a tissue in both hands.
```

5. 保留确定键触发、与人物相同。不要给阿姨加必须完成的任务或疾病说明。

## 四 新增爷爷

1. 墓园事件模式下，双击空格 **(16,7)**，新建事件，名称 `Grandpa`。原工程下一个编号应为 **020**；若你另加过事件，编号不同不影响此步骤。
2. 第 1 页不勾选出现条件。图像选择 `$RM_Grandpa`，**第二行中间帧**，让爷爷朝左、面向家人。
3. 自主移动选择“固定 / Fixed”；移动动画可保留，踏步动画不要勾；不要勾“穿透”。
4. 优先级“与人物相同”，触发“确定键”。
5. 右侧指令空行双击，“显示文字”。脸图 `RM_Face_Grandpa`，**索引 2**；背景“窗口”，位置“下”。只输入：

```text
Grandpa is standing very still.
```

6. 确定、保存。这是旁白观察，不需要加 `GRANDPA` 发言标签，也不需要加开关。

这个站位留出爸爸与 Grace 的主线通道。不要把爷爷放到 (13,7)、(14,7)，也不要放到妈妈稍后会经过的 (13,9)—(13,12)。

## 五 Grace 的角色脸图

数据库 / Database → 角色 / Actors → Grace → 双击脸图，选择你原有的 `RM_Face_Grace`。可选索引 3，保留 `$RM_Grace` 行走图。

这只补角色数据库的脸图，不会自动替换各条对话中的表情。爸爸、妈妈、Grace、奶奶已有对话脸图继续使用你设置的版本。

## 完成标志

叔叔不再使用秃顶老人图；阿姨不再使用灰发老人图；爷爷作为单独角色在场。三个人各有自己的脸图，进入人物选择框时没有切到邻格、只剩半张脸或出现整张图表。


# 闪回与结尾逐步修改

依据：原剧本的 FLASHBACK、RETURN TO CEMETERY 段落，以及 Map001、Map002 的现有事件。下面调整表演与流程，**不改闪回英文对白**。帧数按 MV 常用的 60 帧约 1 秒理解；这些时长是建议起点。

## 一 先给开关命名

在任何“控制开关 / Control Switches”指令的选择框中，可给对应编号改名。只改名称，不改编号，也不额外切换开关状态。

| 编号 | 名称 |
|---|---|
| 0001 | OpeningComplete |
| 0002 | VisitedGrave |
| 0003 | FlashbackActive |
| 0004 | FlashbackComplete |
| 0005 | Act1Complete |
| 0006 | MomCall |
| 0007 | MomHintDelivered |
| 0008 | FlowersSeen |

变量 0001 命名为 `OtherGravesInspected`。若另一台电脑已经使用 0007、0008 做其他事情，需要选空闲开关，并同步替换教程中的编号；不要覆盖已有用途。

## 二 调整进入闪回的位置

1. 墓园地图 → **003 Dad → 第 2 页**，确认出现条件是开关 0002 ON。
2. 找到末尾的“淡出画面 / Fadeout Screen”，在它前面插入“更改菜单访问 / Change Menu Access：禁止”。
3. 找到传送至 `Act1_House_Flashback` 的“场所移动 / Transfer Player”。改为位置 **(12,13)**、方向 **右 / Right**、淡入淡出 **无 / None**。
4. 其余爸爸对白保留。原本已有淡出画面，不要再给传送附加一次淡出。

这里让 Grace 站在走廊入口，先侧身听，再在奶奶叫她时转头。闪回结尾仍回到墓园 (13,7)，面向爸爸；不增加可探索的家中地图。

## 三 调整闪回人物和门边通行

1. 打开 `Act1_House_Flashback`。
2. 把 **002 Grandma** 的事件格移至 **(12,5)**。图像和奶奶的上朝向保留。
3. 把 **003 FlashbackDad** 移至 **(11,6)**，朝上。
4. 切回地图绘制模式，用右键吸取 **(12,5)** 的可通行地面图块，在 **(12,4)** 画一格同样的地面。地图的可见房间是远景图，所以这里主要改变隐形碰撞，不需要重画门。
5. 不要在数据库中把整个图块集的墙都改成可通行。只需要门边这一个站立格。

如果无法确认吸取是否正确，优先使用本包 `Map002.json` 的完整副本；或者保留地图原样，将奶奶停在 (12,5)，取消下一节向上一步。后一种会离门稍远，但不会让强制移动卡住。

## 四 修改 FlashbackController 第 1 页

双击 **001 FlashbackController**。第 1 页保留：条件 **0003 ON**，触发 **自动执行 / Autorun**。第 2 页保留：条件 **0004 ON**，空指令页，防止重播。

只修改第 1 页。可依据下面顺序重排，也可以照 `06_事件指令对照.md` 中 Map002 事件 001 逐条建立。所有移动路线：**不重复、等待完成、不勾“无法移动时跳过”**，因此必须先做好上一节站位和通行格。

| 顺序或对白位置 | 在 MV 中设置 |
|---|---|
| 开头更改色调 | 红 -16、绿 -12、蓝 -6、灰 48；1 帧；等待完成 |
| 紧接色调 | 事件指令第 3 页 → 脚本，输入下方单行镜头代码 |
| 环境声 | 播放 BGS `RM_Room`，音量 16，音调 100，声像 0 |
| 配乐 | 播放 BGM `RM_Flashback`，音量 22，音调 100，声像 0 |
| 随后 | 淡入画面；等待 24 帧 |
| Grandma：`I need to go home.` | 保留原文字和脸图 |
| Dad：`Mom.` / `You are home.` | 保留原文字和脸图 |
| Dad 说完 | 设置移动路线，目标 Grandma：**向上一步**；播放 SE `RM_DoorHandle` 音量 30；等待 20 帧 |
| Grandma：`No.` | 保留 |
| 随后 | 目标 FlashbackDad：**向上一步、向右一步、朝上** |
| Dad：`We talked about this.` | 保留 |
| 随后 | `RM_DoorHandle` 音量 34；等待 18 帧 |
| Grandma：`Grace?` | 保留；随后目标玩家：**朝上** |
| Dad：`Mom, please—` | 保留 |
| 随后 | 播放 SE `RM_DoorPalm` 音量 35；等待 12 帧 |
| Grandma：`Let me go home!` | 保留；等待 24 帧 |
| Dad：`I CAN'T DO THIS AGAIN.` | 保留 |
| 爸爸喊完、玩家确认对白后 | 淡出 BGM 1 秒；淡出 BGS 1 秒；停止 SE；等待 60 帧 |
| 然后 | 目标玩家：**后退一步 / 1 Step Backward**；播放 `RM_Step1` 音量 18；等待 36 帧 |
| 结束 | 淡出画面；0003 OFF；0004 ON；传送墓园 (13,7)，朝右，淡入淡出无 |

镜头脚本只输入这一行：

```javascript
$gameMap.setDisplayPos(3.5, 3);
```

**删除旧版三个震动画面、两个 `RM_Heartbeat`、两个 `RM_KnockHard`、向上滚动地图及相邻的 70 帧等待。** 已有 `RM_DoorPalm` 音效更贴近原剧本的手掌拍门，不需要导入新音频。所有表格未要求保留的旧等待，按新清单替换，避免新旧停顿叠加。

原先最后一条玩家移动是“前进一步”，这会让朝上的 Grace 向冲突走近。这里必须选“后退一步”，不是“向下一步”；后退能够保留她朝向家人的姿态。

最后一秒安静包含音频渐弱过程，不是立即全静音。玩家读对白的时间由玩家自己控制，不设置自动跳过。

## 五 让妈妈走到父女身边

墓园 **010 AfterFlashback_EndAct → 第 2 页**，条件仍为 0004 ON，触发仍是自动执行。

1. 开头插入“更改菜单访问：禁止”。保留恢复色调、雨天、雨声、爸爸站位与淡入。
2. 将 `RM_Act1_Cemetery` 的播放移到“淡入画面”后，先等待 **24 帧**再播，音量 **30**。让返回的雨声先被听到。
3. 保留爸爸的 `Grace?`、`You okay?`，以及 Grace 的困惑独白。
4. 找到妈妈第一次说 `Grace. We're going home now.` 的位置，在这条“显示文字”**之前**插入：
   - “设置事件位置 / Set Event Location”：Mom，直接指定 **(13,12)**，朝上。
   - “设置移动路线 / Set Movement Route”：目标 Mom，**向上一步，连续四次**；不重复，等待完成，不跳过。
5. 妈妈说完这一句后，删除旧的五条：淡出画面、淡出 BGM 1 秒、把 Mom 放到 (8,14)、把玩家传送到 (9,14)、淡入画面。只删这个中段黑屏转场，**不要删第一幕最后的黑屏**。
6. 接着直接播放 `RM_Box`，音量改为 **32**；保留妈妈介绍盒子、显示 `RM_Box` 图片、`For Grace.` 等所有英文对白和结尾。
7. 第 3 页仍是 0005 ON 的空指令页。末尾 0005 ON 和返回标题也保留。

妈妈重新定位后走到 (13,8)，站在 Grace 后方。这一段没有第二次黑屏，没有新增场景，也没有提前打开盒子。

## 完成标志

奶奶拉门时站在门边；爸爸朝向奶奶；Grace 在被叫到名字后转头，喊声结束后真的退一步。返回时先听到雨声，随后妈妈走来，剧情接上原有遗物箱段落。


# 游玩体验逐项设置

建议按顺序做。人物、主线推进条件和结局不新增任务；环境观察仍然可选。

## 一 开场音量和操作说明

墓园 **001 OpeningController → 第 1 页**：

1. `RM_Act1_Cemetery` 的音量从 50 改为 **32**。雨声 35、雨天强度 2 可以先保留。
2. 开头“更改菜单访问”改为**禁止**；原有“更改保存访问：允许”保留。
3. 在最后开启 0001 的位置后插入“更改菜单访问：允许”，然后结束事件。
4. 将原操作说明替换为同一窗口内四行，脸图无、窗口背景、下方：

```text
\C[7]CONTROLS\C[0]
Arrow keys: Move
Enter / Space: Look or talk
Esc: Pause / save
```

这样过场不打开菜单，自由探索时可暂停和保存。原工程已经允许保存，不必再增加自动存档。

## 二 妈妈的长对话只说一次

墓园 **002 Mom → 第 1 页**：

1. 在原指令之前插入“条件分歧 / Conditional Branch”：独立开关 A 为 **OFF**，勾选“创建否则分支”。
2. 把原有的整段母女对话剪切到条件成立的分支内部，保留原等待和脸图。
3. 原对话末尾加“控制独立开关 / Control Self Switch：A = ON”。
4. 否则分支放一条“显示文字”：Mom 脸图索引 1，输入：

```text
\C[6]MOM\C[0]
I'll be right here.
```

5. 分支结束后没有其他指令。第 1 页不增加出现条件，不新建一个覆盖第 2 页的页面。

若你的 Mom 事件已经使用独立开关 A，请改用空闲的独立开关，并同步替换条件与设置。

## 三 修正妈妈探索提示

墓园 **002 Mom → 第 2 页**：保留出现条件 **0006 MomCall = ON**，自动执行。把右侧指令改为以下结构：

```text
条件：0002 VisitedGrave 为 OFF
  条件：0007 MomHintDelivered 为 OFF
    显示文字：RM_Face_Mom，索引 1，窗口，下方
      \C[6]MOM\C[0]
      Grandma's stone is near Dad.
      I'll be right here.
    控制开关：0007 = ON
  分歧结束
分歧结束
控制开关：0006 = OFF
```

**0006 OFF 要放在两个条件分歧外面**，否则自动执行可能一直重复。0007 用于保证这句提示只出现一次；0002 防止看完主墓碑后再被叫去看。

其他墓碑中现有的“独立开关 B、变量 0001 加一、达到四次开启 0006”的计数逻辑保留。它只触发提示，不是主线通关门槛。

## 四 两边的白花共享重复对白

墓园 **005 WhiteFlowers** 和 **018 WhiteFlowers** 都做同样处理：

1. 用“条件分歧：0008 FlowersSeen 为 OFF”包住原来的音效与完整对白，勾选否则分支。
2. 完整对白最后添加“0008 = ON”。
3. 否则分支放 Grace 脸图索引 7：


# 更换默认英文字体

**本次推荐先用 Arial，字号 26，描边 2。** 这是便于阅读的起始设置，不是必须采用的美术标准。若你更喜欢其他字体，可按本文最后一节替换。

## 为什么之前改字体可能没生效

这两个原因来自你提供的工程代码和文件：

- `System.json` 的 `locale` 是 `zh_CN`。`rpg_windows.js` 会给中文项目选择 `SimHei, Heiti TC, sans-serif`，不采用 `GameFont`。因此只改 CSS，窗口里的英文可能仍没变化。
- `fonts/gamefont.css` 的兜底文件写成 `mplus-1m-regular.woff`，但当前文件夹实际只有 `mplus-1m-regular.ttf`。本包修正了这个路径。

本包用独立插件明确指定窗口字体，无需你修改引擎核心 JS，也无需通过改系统语言来绕过问题。

## 方法 A 使用系统字体

1. 关闭另一台电脑上的游戏运行窗口和 MV 编辑器。
2. 在工程副本的 `fonts` 文件夹，把原 `gamefont.css` 复制一份，命名为 `gamefont_before_changes.css`，用于恢复。
3. 将本包 `assets/fonts/gamefont.css` 复制到工程副本的 `fonts`，替换同名 CSS。
4. **保留工程已有的 `mplus-1m-regular.ttf`**。本包没有重复附带这个字体文件。
5. 将本包 `assets/js/plugins/RM_EnglishTypography.js` 复制到工程的 `js/plugins`。
6. 打开 MV，工具 → 插件管理器，双击空白行，名称选择 **RM_EnglishTypography**，状态 ON。
7. 如果也安装体验插件，将字体插件放在 `RM_Act1_Experience` 后面；如果有其他字体或对话插件，也将本插件放在它们后面，并留意是否重复控制字体。
8. 在参数栏分别双击设置：

| 参数 | 填写内容 |
|---|---|
| Font Family / FontFace | `Arial, Helvetica, sans-serif` |
| Font Size / FontSize | `26` |
| Text Outline Width / OutlineWidth | `2` |

9. 确定，保存工程。关闭旧的游戏窗口，在另一台电脑重新启动游戏，观察英文对白和菜单。

Arial 不存在时会依次使用 Helvetica 或系统默认无衬线字体。这种方式不需要下载或分发字体，但不同电脑的最终字形可能不同。

## 调整字号和描边

仍在插件参数中改，不要把每条对白手工加上变字号控制符。

| 你的感觉 | 可以试的数值 |
|---|---|
| 26 号仍显拥挤 | 字号 24，描边 2 |
| 26 号太小 | 字号 28，检查长句是否超出窗口 |
| 字体边缘太厚 | 描边 1 |
| 背景复杂、文字看不清 | 描边 2 或 3 |

原来的行高 36、脸图大小 144×144 保留，所以调整字号不会改变脸图格子。字体变宽后，MV 不保证自动折行；过长的一行应在“显示文字”里手动换行。每个消息窗口最多四行，角色名本身也占一行。

体验插件底部的互动提示使用独立的 20 号字，不跟随对话字号参数。当前默认同样采用 CSS 提供的系统字体；如果你只改变 FontFace，这条小提示不一定一起变化。

## 方法 B 每台电脑显示同一种自定义字体

适合你已经选好并且有权随游戏分发的字体。本包**没有附带第三方字体文件**，不要把 CSS 示例误当成字体。

1. 准备可用于游戏分发的**静态常规体 TTF**，同时保留随字体提供的授权说明。优先避免老版 MV 运行环境可能不能正确处理的可变字体。
2. 将该字体文件复制到工程 `fonts`，命名为 **CustomFont.ttf**。确认系统没有把它变成 `CustomFont.ttf.ttf`。
3. 备份现有 `gamefont.css`。
4. 用记事本打开 `gamefont.css`，将全部内容替换为以下代码，再保存。保存类型选“所有文件”，不要生成 `gamefont.css.txt`：

```css
@font-face {
    font-family: GameFont;
    src: url("CustomFont.ttf") format("truetype");
    font-weight: normal;
    font-style: normal;
}
body {
    font-family: GameFont, sans-serif;
}
```

也可以复制本包 `generation/custom-font-example.css` 到工程 `fonts`，再改名为 `gamefont.css`。**必须先放好 CustomFont.ttf，再使用这份示例。**

5. 插件管理器 → RM_EnglishTypography → **FontFace 改成 `GameFont`**，字号先保留 26、描边 2。
6. 保存、关闭旧游戏窗口、重新启动。部署时确保 `fonts/CustomFont.ttf`、CSS 和字体授权说明都在发行包中。

使用方法 B 后，CSS 不再优先引用系统 Arial。你选的字体会用于 GameFont 绘制的文字；设置 FontFace=`GameFont` 才能让对话窗口也使用它。

## 不会跟着改变的文字

标题背景图片里已经画进去的 `Remember Me`，以及 `RM_Box` 图片上的 `For Grace`，都属于图片像素，字体插件无法改变。它能改变的是游戏运行时绘制的窗口文字、菜单等。

“编辑器界面字体”和“游戏字体”也不是同一设置：这份教程只改游戏，不改变 MV 编辑器的中文界面。

## 恢复与排错

- 字体没变：确认插件状态 ON、名称未改、排在其他字体插件后面；若用自定义 TTF，确认 FontFace 是 `GameFont`。彻底关闭旧游戏窗口再启动。
- `Failed to load GameFont`：检查 CSS 的文件名、扩展名和大小写；方法 A 要有原来的 `.ttf`，方法 B 要有 `CustomFont.ttf`。不要把文件夹路径放进字体名称参数。
- 想恢复：关闭插件，把备份 CSS 复制回 `gamefont.css`。原项目未改变，随时可回到原工程。

本节根据工程源码准备，按你的要求未在本机运行新字体设置。最终字形、字号与部署结果由你在另一台电脑确认。

| 现象 | 检查位置与处理 |
|---|---|
| 角色变成一大片、只有半个人 | 文件名是否保留 `$`；是否误把脸图放进 characters；是否选择中间站立帧 |
