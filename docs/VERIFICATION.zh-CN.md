# 验证记录 — 构建到底能不能跑起来？

在本仓库发布之前，`game/` 中随仓库发布的构建在真实浏览器里跑过，并从 **New Game** 一路驱动到第一幕结束。本文件如实记录做了什么、观察到了什么，以及*没有*测试什么。

截图在 [`screenshots/`](screenshots/) 中。

---

## 方法

- 通过 HTTP 提供 `game/`（`python3 -m http.server`），并在 Chrome 中加载 `index.html`。
- 通过 DevTools 协议驱动浏览器：使用游戏自身的输入层（`Input._onKeyDown` / `Input._onKeyUp`），而不是合成操作系统按键事件，因为 RPG Maker MV 每帧只轮询一次输入，短于一帧的按键会被丢弃。
- 在按键之间读取引擎的实时状态：当前场景、`$gameMap._mapId`、玩家位置、八个开关、`$gameMessage.isBusy()`、`$gameMap.isEventRunning()`。
- 游戏在测试浏览器中稳定运行在 60 fps。

---

## 结果：这一章能走完

| 步骤 | 预期 | 实际观察 |
|---|---|---|
| 启动 | 标题画面显示 `GAME START / CONTINUE / SETTINGS` | ✓ |
| 开始新游戏 | `Scene_Map`，Map 1，玩家位于 (12,12)，开场消息正在运行 | ✓ 按 1 次后 |
| 播放冷开场 | 结束时开关 1（`OpeningComplete`）为 ON，玩家可以自由移动 | ✓ 按 12 次后 |
| 进入闪回 | Map 2，玩家位于 (12,13)，闪回的自动执行事件正在播放 | ✓ |
| 播放闪回 | 结束时开关 3 为 OFF、开关 4（`FlashbackComplete`）为 ON，玩家回到 Map 1 的 (13,7) | ✓ 按 14 次后 |
| 播放结局 | 结束时开关 5（`Act1Complete`）为 ON | ✓ 按 24 次后 |
| 结局之后 | 回到标题画面（指令 354 = *Return to Title Screen*） | ✓ |

**没有 JavaScript 错误，也没有卡住的画面。**`data/*.json` 引用的全部 229 个图片与音频文件都确认存在于磁盘上，运行期间浏览器发出的每个请求都以 HTTP 200 返回。最终状态的日志行是：

```
{"scene":"Scene_Title","map":1,"x":13,"y":7,"sw":"11111000","busy":false,"run":true}
```

`sw:"11111000"` 是开关 1–8，也就是 1 到 5 为 ON、6–8 为 OFF — 正是结局本该留下的状态。

## 过程中做过的检查

- **自定义图片的几何尺寸** — 所有 `RM_*` 素材都符合引擎的网格规则：`$RM_*` 行走图为 144 × 192（3 × 4，每格 48 × 48）；脸图为 576 × 288（4 × 2，每格 144 × 144）；标题为 816 × 624；两张视差图为 1152 × 864；碰撞图块组基于 48 px 网格；`Window.png` 为 192 × 192。
- **没有缺失素材** — `data/*.json` 引用的每个图片和音频文件都存在于磁盘上，引用的每首音频都以 `.ogg` 和 `.m4a` 两种格式存在。
- **没有加密** — `System.json` 中没有 `hasEncryptedImages` / `hasEncryptedAudio` 键，因此明文工程文件可以直接从静态主机加载。（加密正是让工程在作为明文文件提供时无法运行的原因。）
- **碰撞层行为正常** — `Tilesets.json` 中图块 1536 的标志位是 `1536`（低半字节为零 → 可通行），图块 1537 的标志位是 `1551`（低半字节 `0x0F` → 四个方向都不可通行），这与图块组自身的备注一致：*“A5 tile 1 = walkable, tile 2 = blocked.”*
- **事件指令内部自洽** — 对两张地图中的开关与变量读写做了追踪；每个在某处被判断的开关都在某处被赋值，八个开关也都有名称。

## 没有测试的内容

在展示这项工作时，把这一点说清楚。

1. **没有打开 RPG Maker MV 编辑器。**这里的一切都只关于运行时。本次会话中没有用 MV 1.6.1 打开并重新保存过该工程，所以如果存在编辑器层面的问题（插件参数改动、图块组指定），那是不曾被看到的。
2. **没有走完通往 Dad 的自然步行路线。**测试直接设置了 `VisitedGrave` 开关并跳进闪回，完全复刻了 Dad 事件所做的事，但中间那段行走、墓碑交互、查看花与旧坟、Mom 的呼喊，以及四个配角，都没有通过输入实际操作过。
3. **没有打开菜单。**测试中从未按过 `Esc`，而菜单在开场期间被禁止、之后才允许，所以这一点两种情况都没有被观察到。
4. **两个已知缺口仍然存在**，而且是被观察到存在、而非已修复：闪回仍然播放两次画面震动和两个 `RM_KnockHard` 音效，系统语言仍然是 `zh_CN`，所以系统文本是中文。完整清单在 README 的 “Build state” 一节。
5. **只在 Chrome、只在桌面端。**没有测试 Safari 和 Firefox。需要留意的是 Safari，因为它需要 `.m4a` 音频而不是 `.ogg`。
6. **没有人工的本地试玩。**这是一次自动化运行，没有对音频做验证。
