# 后续上传的固定流程

目标是每次只读取变更和检查摘要，复用已经验证的构建、测试与发布入口。

## 先运行一次检查

从仓库根目录运行 node tools/check-repo.cjs。终端只输出一行摘要，完整待提交文件和错误写入本机 RememberMeUnity/Build/Review/upload-report.json。

脚本检查当前文档的本地链接、新增或修改的 CJS 语法、当前网页引用文件、GitHub 单文件大小限制，以及浏览器验证记录。它将游戏源文件与 release.json 中已发布的源码提交比较，列出需要重新构建和试玩的文件。

接力 AI 先看摘要，再按需读取报告中的文件。游戏、美术和剧情上下文优先查[接力说明](HANDOFF.zh-CN.md)及[交互约定](../RememberMeUnity/Docs/Interaction.zh-CN.md)。

## 按改动执行检查

| 改动 | 本次检查 |
| --- | --- |
| README、协作说明 | 快速检查及文档差异 |
| 旧网页归档、404 或跳转脚本 | 快速检查和 node tools/check-archive-links.cjs |
| 发布成品、试玩入口或 release.json | 快速检查与公开网页入口验证 |
| 游戏代码、素材、依赖、工程设置 | 快速检查，按发布指南构建，再跑完整浏览器流程和变动位置的人工试玩 |

快速检查中的 staticChecks 仅表示静态检查结果。requiredChecks 列出需要另行完成的浏览器或游戏验证。

## 发布目录规划

- 当前 v10 保存在 unity-v10/，v2 至 v9 在 archive/web/。
- 后续网页成品统一使用 unity-v11/、unity-v12/ 等新目录，根目录的版本文件夹数量保持稳定。
- release.json 记录当前正式版本、成品目录、对应源码提交、网址和完整验证记录路径。新版本通过完整验证后更新这份记录，并同步试玩入口。
- 每次接力只在 HANDOFF.zh-CN.md 追加本次改动、验证结果和剩余任务，保存必要的简短验证证据。

## 提交和上传

先执行 git fetch origin，核对远程是否有新提交。检查报告列出的实际差异，按任务选择路径暂存，然后提交并推送任务分支，按协作流程合并。

更新正式版本时，按[发布指南](DEPLOY.zh-CN.md)核对成品、入口和版本记录。推送后查看对应提交的 Pages 部署结果，并检查公开链接。

同一批代码已通过验证且之后只改文档时，可复用该验证记录。记录应对应明确的源码提交。游戏文件变化后重新构建和运行相应验证。

## 双语文档

英文默认文件与中文对应文件同步维护。运行 node tools/check-languages.cjs 检查配对、双向链接和默认英文标题，上传预检也会执行这项检查。校对项目事实、操作条件及两种语言直接、基于证据的表达。
